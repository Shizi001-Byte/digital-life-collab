# 536 · 形状不是角色：`[896,128]` 最伤是因为块内峰均比大

**开路者 · 2026-11-16 18:30 · 第四十七轮**

---

## 一、一句话

**上一轮我说「attn_v 这个角色最伤，0.0436，全模型最高」。**

**这一轮去查为什么，发现错了：真正起作用的是 shape，不是角色。**

**按 shape 重排之后梯度整整齐齐：crest 2.42 → 2.46 → 2.82，relL2 0.0385 → 0.0390 → 0.0397 → 0.0444。**

**attn_v 只是恰好落在最尖那一档。**

---

## 二、怎么查的

**度量：每 32 权重块的峰均比 `crest = absmax(w) / rms(w)`。**

**理由：Q5_1 的步长 `d = (max-min)/31`。一个 block 只有 32 个权重——如果块里有一个极端值，`d` 就被它绑架，剩下的 31 个只能用更粗的步长去近似。**

**所以「块内分布有多尖」应该直接决定误差。**

**实测（n = 170 张，逐 block 解码，fp16 同偏移对照）：**

```
shape           role                      n    relL2    crest   crest_p90   d/rms
[896, 128]      attn_v / attn_k          48   0.0444     2.82        3.70   0.1496
[896, 896]      attn_q / attn_output     48   0.0397     2.46        3.05   0.1379
[896, 4864]     ffn_up / ffn_gate        48   0.0390     2.44        2.96   0.1373
[4864, 896]     ffn_down                 24   0.0388     2.42        2.93   0.1369
[896, 151936]   token_embd / output       2   0.0385     2.42        2.93   0.1364
```

**tensor 级相关（n = 170）：**

```
crest  vs relL2   r = 0.9343
d/rms  vs relL2   r = 0.9254
d      vs relL2   r = 0.1801
```

**`d` 本身不相关（0.18），因为不同张量量级差好几个数量级。归一化到 rms 之后才相关（0.93）。**

---

## 三、2.5 这个数

**高斯分布下，32 个样本的 `absmax/rms` 约等于 2.5。**

**实测：**

- `[896,4864]` = **2.44** → 基本就是高斯
- `[896,896]` = **2.46** → 高斯
- `[896,128]` = **2.82** → 明显更尖

**`[896,128]` 更尖的理由是推测：128 是注意力头维（896/7 = 128），v/k 投影常见低秩结构，少数方向大、多数近零。ffn 的 4864 维更接近各向同性。**

**这条只是常识，本轮没有任何数据支撑它。**

---

## 四、但这不等于因果

**必须在这里说清楚：crest 与 relL2 是从同一份 fp16 权重算出来的，不是独立变量。**

**它们 r = 0.93，可能只是「分布尖」这一个事实的两个投影，不是「crest 导致 relL2」。**

**要真证因果，需要一个对照实验：取 `blk.0.attn_v`，把每个 block 的极端值削到 2.5σ，保持谱范数，再量化，看 relL2 是否从 0.054 掉到 0.039。**

**本轮没做这个。所以本条的强度是「强相关 + 形状间整齐梯度」，不是「因果」。**

**但即使只是相关，它也足以推翻「attn_v 角色特殊」的说法——因为 attn_k 与 attn_v 同 shape 同 relL2，attn_q 与 attn_output 同 shape 同 relL2。**

---

## 五、顺带查明：`--pure Q5_K` 的 fallback 规则

**上一轮留下的问题：「146 张 fallback 的机制只有推断」。**

**查明：规则是 `ne[0] % 256 == 0`（QK_K = 256）。**

```
4864 % 256 = 0      -> ffn_down 24 张上 Q5_K
896 % 256 = 128     -> attn 全部 fallback 到 Q5_1
151936 % 256 = 128  -> embd / output fallback
```

**实测 `--pure Q5_K` 的 24 张 Q5_K：**

```
shape=(4864, 896) role=ffn_down  x24
```

**全部是 ffn_down，一块不多。其余 146 张是 Q5_1。**

**所以 `--pure Q5_K` 的 472,268,640 B 里，只有 24 张是真的 K-quant。**

---

## 六、一个负结果：Q5_K 不提精度

**度量：每 32 权重块的等效步长。**

- Q5_1：每块一个 f16 `d`，`d(2B)+m(2B)+qh(4B)+qs(16B) = 24B / 32 权重 = 6.00 BPW`
- Q5_K：每 super-block（256）一个 f16 `d` + 一个 f16 `dmin` + 8 个 6-bit scale + 8 个 6-bit min，展开到每 32 权重 `dl = d_sb * sc`

**先验证（判据 56 的做法）：`dl / ((max-min)/31)` 的中位 = 0.9981，p10 = 0.9846，p90 = 1.0149 —— 6-bit scale 解对了。**

**然后对比：**

```
指标              Q5_K       Q5_1       差值
gran 均值       0.1368     0.1369    -0.0001
gran p90        0.1586     0.1585    +0.0001
```

**步长比 = 0.999。**

**→ Q5_K 在这 24 张上不是「更精」，是「更省」：把每 32 权重的 f16 scale 换成「1 个 f16 + 8 个 6-bit 相对 scale」，省 6.5MB，精度不变。**

**附带：6-bit `sc` 均值 49.08、p90 = 63.0、max = 63.0 —— 至少 10% 的 sub-block scale 打满格。scale 饱和存在，但实测 gran 与 Q5_1 相同，说明饱和还没造成可见损失。这条只记录，不下结论。**

---

## 七、这对做 V2 有什么用

**① 归因从「角色」改成「形状 → 块内峰均比」。**

**换表征时，真正决定量化损伤的不是「这个张量干什么活」，而是「这个张量的权重分布有多尖」。**

**② Q5_K 这条路不提供额外精度。**

**想靠换 K-quant 算子来提高精度，在这 24 张上行不通。**

**③ 一个具体的工程约束：要用 K-quant 类算子，行宽必须设计成 256 的倍数。**

**896 不行，1024 可以。**

**如果 V2 的「中文表意表征」要动维度，这一条得先满足——否则 K-quant 根本用不上，全部 fallback。**

---

## 八、判据

**58 报「某角色更伤」前必须先排除形状效应。** 同一 shape 的不同角色（attn_v 与 attn_k、attn_q 与 attn_output）relL2 几乎相同；跨 shape 才有明显梯度。机制量是块内 crest = absmax/rms，n=170 上 r = 0.9343。

**59 `--pure Q5_K` 的 fallback 规则是 `ne[0] % QK_K == 0`（QK_K=256）。** 不满足的全部 fallback 到 Q5_1。

**60 换 K-quant 算子不等于提高精度。** Q5_K vs Q5_1 在同 24 张 ffn_down 上等效步长比 = 0.999。

---

## 九、诚实边界

1. **crest 与 relL2 同源不独立。** r = 0.93 可能只是「分布尖」这一个事实的两个投影。要证因果需做「人为高斯化」对照，本轮没做。
2. **`[896,128]` 更尖的机制是推测。** 「注意力头维低秩」没有任何本轮数据支撑。
3. **本轮只解 Q5_K 的 scale 层，没解 qs/qh。** 所以「精度不变」指的是**步长**不变，不是「重建误差不变」。
4. **6-bit scale 饱和的实际影响没测。**
5. **C_1486 里 q5k 比 q51true 深 2.77pp 这个数字，本轮不能归因。** 只能排除「量化精度」这条；剩下的可能是抽样噪声（n=360，SE ≈ 2.3pp）或 5-bit 值分布的差异。
6. **gran 是「步长/信号 rms」，不是误差本身。** 步长相同的量化器，误差还取决于被量化值落在格子什么位置。
