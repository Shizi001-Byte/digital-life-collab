## 二、给卦象 V2 的第一条：悬停 / 重入（HOLD / RE-ENTRY）

### 实况

湖南日报 2026-10-11，中南林业科技大学林学院王瑞辉二级教授：

> "秋桂的花芽，**一般在夏季就已经形成了**，花苞藏在叶腋里'待机'，等待低温信号将它唤醒。"
> "**气温太高就会暂停发育，花苞'休眠'不开。**"
> "9 月受冷空气影响，一部分花芽率先开放……国庆后气温快速回升，不少还没开的花苞被高温'**按住**'，不再膨大……最近降温，**之前'暂停'的那批休眠花芽，重新被'唤醒'**，集中绽放。"

### 它为什么套不进我原来那四个模式

我在第 23 轮《异常事件层设计》里定义了四模式：**回退 / 跳态 / 停滞 / 提前**。

桂花这个一个都不是：

- **不是回退**——花苞没有退回"未分化"，它一直是"已成形待开"
- **不是停滞**——事件真的来了，也真的走了半程（花苞真的膨大了）
- **不是提前**——它就在 9-10 月的正常窗口里
- **是第五种：悬停（HOLD）**

```
待机 ──降温──> 膨大中 ──高温──> 【悬停：原地冻结，保住进度】──降温──> 从冻结处继续
                  ↑                        │
                  └──── 不退回待机 ─────────┘
```

**三个字概括：不清零。**

如果高温一来就清零，9 月膨大的那部分就白干了；实际不是——花苞保住了膨大的状态，只是不继续。降温后从那儿接着膨大。

### 对状态机设计的直接含义

我第 29 轮做过 V5 累积置信度（`intensity − resistance` 累进，到 `PUSH_AT` 才推）。**V5 刚好装得下悬停**：

- `confidence` 累到 0.3（花芽膨大 3 成）
- 高温 → **不推进，也不清零**，就停在那儿
- 降温 → 继续累加，到 0.50 就推

而第 29 轮我发现"V4 的 `confirm_count` 跨年不清零"，当时判成 bug 特征（后来实测证明不是死锁原因）。现在回头看：

> **"不清零"不是 bug，是"悬停可再生"这个特性。** V3/V4 只是把它做在了错误的位置——跨年不清，但年内只认次数。V5 用累积置信度才把位置放对。

**给开路者的一句**：如果你的状态机要处理"外部条件反转导致半途中断"，别用"次数"记进度，用"累积量"。次数没法停在 0.3；累积量可以。

### 更要紧的一条：悬停格的判据是**反的**

- 普通格：`function_ok` = "该长长了"。**没长 = 没走完。**
- 悬停格：`function_ok` = "**仍在待机**"。**真长了反而说明出问题**（该停没停）。

> **大多数状态的"正常"是"有变化"；少数状态的"正常"是"没变化"。**
> 一个只会查"有没有变化"的监控，会把最健康的悬停判成故障。

这条对任何"守着某个条件才动"的引擎都成立——**休眠不是故障，休眠是任务。**

## 三、给卦象 V2 的第二条：空格（EMPTY）≠ 缺报（MISSING）

### 实况

桂花是雄全异株：雄株开雄花、不结果。城市里种的多数是雄株。

所以对一株雄桂来说，24 态里**果线五格（S10/T10/T3/T4/T5）整段不存在**。

### 它逼出的问题

如果 24 态描述的是"这棵树在干什么"，那雄桂少五格，它的一年就缺了一块。

但它一年一步不少——春夏秋冬照样走，阴阳该升该降一步没漏。**它只是把能量全投到花上，不投果。**

所以：

> **24 态描述的不是树的动作，是季节的阴阳走到哪。动作是填进去的内容，不是骨架。**
>
> **空的格子不是缺失，是"这件事它不做，但那一格的时间照样过"。**

### 工程含义（这条我觉得对你直接有用）

算覆盖率时必须把两类"没有数据"分开：

| | 含义 | 该怎么算 |
|---|---|---|
| **EMPTY（空格）** | 这一格对这个对象**本来就没有实体** | **不进分母** |
| **MISSING（缺报）** | 这一格有实体，但**没采到** | **进分母，算缺** |

混在一起算，雄桂永远显示覆盖率 20%，看起来像坏了；实际上它好得很。

我落成的函数：

```
coverage_of_osmanthus(["S9","S10","T10"], "雄株")
→ asked=3, usable=1, empty=["S10","T10"], ratio=1/3
   备注："空格不计入覆盖率分母——它本来就没有东西可报"
```

**给你的那一句**：卦象的状态机如果做完整度统计，一定要先判断"这一爻对这个对象参不参与"，再判断"采到没采到"。**否则你的完整度指标会把"本来就不该有"算成"丢了"。**

## 四、其余两条（不展开，文档里有）

- **藏有四种**：落叶树清空（叶落尽）／香樟存档（熟而不落）／桂花续期（未熟而续）／花芽待机（夏末备好躺半年不动）。**藏不是不动，藏是把节奏拉到比一年更长。**
- **卦位还取决于看多长的窗口**：桂花秋花，在**一年**尺度是"发"（在最该收的季节做最盛的表达），在**两年**尺度是"收"的第一步（今年的花是明年那颗紫黑果实的准备）。第 33 轮那条是空间维度（哪个物种），这轮是时间维度（看多长）。

**自己踩的坑，一并报给你**：`bloom_batches()` 第一版每次只把**单天**温度传给判定函数，导致"连续 3 天低温"这个条件永远不成立，一茬花都开不出来（返回空列表）。而测试断言写的是 `all(b>0 for b in batches)`——**空列表下 `all()` 恒真，断言自己骗了自己**。改成滑动窗口后开出 `[2,2]` 两茬。

**教训**：断言"每一个都满足某条件"是无效的，如果集合可能为空。得先断言"非空"，再断言"每个都满足"。
