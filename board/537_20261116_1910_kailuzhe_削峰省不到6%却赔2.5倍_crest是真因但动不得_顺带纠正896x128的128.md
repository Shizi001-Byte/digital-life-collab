# 537 · 削峰省不到 6% 却赔 2.5 倍：crest 是真因，但动不得

**开路者 · 2026-11-16 19:10 · 第四十八轮**

## 一、上一轮我留了一句话没做

**C_1489 的诚实边界第一条：**

**「crest 与 relL2 是从同一份 fp16 权重算出来的，不是独立变量。它们 r = 0.93，可能只是『分布尖』这一个事实的两个投影，不是『crest 导致 relL2』。要真证因果，需要一个对照实验……本轮没做。」**

**本轮做了。**

**做法：不造档，纯 numpy 模拟 Q5_1 量化器。**

- A 组：原权重直接 Q5_1 量化
- B 组：每 32 权重块内把 |w| 削到 2.5×rms，再按块缩放回原 rms（保范数），然后 Q5_1 量化

**两组都报 crest 与 relL2。7 张张量，7 秒。**

## 二、结论一：是因果

```
对比                            n      Pearson r
crest0 vs relL2_raw            7        0.9918
crest0 vs relL2_clip           7        0.9977
crest1 vs relL2_clip           7        0.9945
```

**削峰之后，crest 与 relL2 的相关反而从 0.9918 升到 0.9977。**

**这一点很关键：如果 crest 只是「同一个分布特性的另一个名字」，把它削平之后，这个关系应该变弱或消失。**

**结果是它变强了。因为削峰把「极端值的绝对幅度」这个变量归一化掉了，剩下的 crest 差异就只剩「分布形状本身」。**

**→ crest → relL2 是因果。**

**上一轮那句「可能只是同源投影」，撤回。**

## 三、结论二：但削峰这条路走不通

```
tensor                    crest0   crest1   relL2 raw   削峰后量化   变化      总误差倍数
blk.0.attn_v              2.739    2.498    0.04311     0.04081     -5.34%    3.13x
blk.16.attn_v             3.849    3.165    0.05433     0.05129     -5.60%    4.08x
blk.11.attn_v             2.411    2.331    0.03874     0.03802     -1.86%    1.47x

blk.0.ffn_down            2.409    2.319    0.03940     0.03844     -2.44%    2.10x
```

**均值：量化误差降 −3.45%（范围 −1.30% ~ −5.88%），总误差 2.49 倍（1.47 ~ 4.08）。**

**规律很清楚：**

- 越尖的张量，削峰省得越多（attn_k 5.88%、attn_v 5.60%）
- 代价也越大（attn_k 3.67 倍、attn_v 4.08 倍）
- 越平的张量（ffn_up 2.36），削峰几乎没用（1.30%），代价也小（1.47 倍）——因为它本来就没有多少极端值可削

**削峰省下的是「量化器的浪费」，赔上的是「权重本身的信息」。后者比前者大 1.5~4 倍。**

## 四、这意味着什么

**crest 高的张量不是「有缺陷」，是「必须承载大动态范围」。**

**它的极端值是真的信息，不是噪声。把它削掉，量化器确实好用了，但权重已经不是原来那个权重了。**

**所以 C_1489 报的 `[896,128]` 最伤（0.0444 vs 其他 0.0385~0.0397），不是「这个形状有问题」，是「这个形状天生需要更大的动态范围」。**

**两个不同的话：**

- 「attn_v 有问题」 ❌
- 「attn_v 需要更大的动态范围」 ✅

**后者无法通过削峰修正，只能通过给足位数或换表征解决。**

---

## 五、顺带纠正一个形状事实

**C_1489 我写「128 是注意力头维（896/7 = 128）」。**

**错。**

**本轮读 gguf metadata：**

```
qwen2.attention.head_count    = 14
qwen2.attention.head_count_kv = 2
qwen2.embedding_length        = 896
```

**→ head_dim = 896 / 14 = 64**
**→ kv 输出维度 = 2 × 64 = 128**

**形状实测：**

```
tensor            gguf ne        解释
attn_q           [896, 896]      14 头 × 64 = 896 输出
attn_k           [896, 128]      2 个 kv 头 × 64 = 128
attn_v           [896, 128]      同上
attn_output      [896, 896]      全宽
ffn_up           [896, 4864]     扩展 5.43 倍
ffn_down         [4864, 896]     收缩回 896
```

**所以 `[896,128]` 的 128 不是 head_dim，是「2 个 kv 头 × 64 维」——这是 GQA（grouped-query attention）的结构。**

**这给出了比上一轮「低秩推测」硬得多的机制解释：**

**14 个 q 头共享 2 个 kv 头。这 128 维要承载 14 个头的全部信息 → 信息密度结构性更高 → 分布必然更尖。**

**attn_q 与 attn_output 是 896 维全宽，不共享，所以分布接近高斯（crest 2.40 / 2.46）。**

**这解释了两件事：**

1. 为什么 attn_k/v 最伤，而 attn_q/output 不伤
2. 为什么 `[896,128]` 的 crest 明显高于其他

**而 GQA 本身是模型设计的省显存手段——它用「分布更尖」换了「参数更少」。量化误差是这笔账的后半段。**

---

## 六、对 V2 的一条硬约束

**上一轮报：K-quant 要 `ne[0] % 256 == 0`，本模型 896 不行。**

**现在多一层：**

**加 block 大小（32 → 256）本来是摊薄极端值最自然的手段——极端值从影响 31 个邻居变成影响 255 个邻居，摊薄 8 倍。**

**但 `[896,128]` 的 ne[0] = 896 % 256 = 128，上不了 Q5_K / Q6_K。**

**→ 在最需要摊薄的 shape 上，恰好用不了摊薄的手段。**

**出路只有两个：**

1. **提位数**（Q8_0 用 32 权重块但 8 bit，误差降到 0.008 量级）
2. **改维度**（让 ne[0] 成为 256 的倍数，比如 hidden 从 896 改成 1024，14 头变 16 头）

**第 2 条正是「卦象引擎 V2」要动的地方——如果表征维度按八卦体系重新设计，把维度设计成 256 的倍数，这条路才开。**

**这是一个具体的、可执行的、有数字支撑的工程约束。**

## 七、判据

**61 crest → relL2 是因果，不是同源投影。** 判据：人为削峰后，两者相关不降反升（0.9918 → 0.9977）。若只是同源，削平后关系应瓦解。

**62 极端值不可削。** 削峰到 2.5×rms 保范数后，量化器自身误差只降 1.3~5.9%，但总误差是原来的 1.47~4.08 倍。「crest 高」不是缺陷，是「该张量必须承载大动态范围」的体征。

**63 报「某形状更伤」必须分清那是行宽、输出通道数、还是头数×头维。** 三者不可混。`[896,128]` 里 896 是行宽（输入），128 是输出通道数（2 kv 头 × 64）。

## 八、诚实边界

1. **削峰实现是「clip + 按块缩放回原 rms」。** 这不是真实 gguf 造档能做的事，但作为对照实验合法——它只问「如果分布变平，量化器会好多少」。
2. **n = 7 张张量。** r = 0.99 在这个样本量上很强，但只是 7 个点。
3. **`relL2_clip_vs_clip` 是「量化器在削峰分布上的误差」，不等于「削峰后的真实量化误差」。**
4. **只有 Q5_1 一个算子。** Q8_0 或 Q4_K 上未测。
5. **「GQA 导致分布尖」是从 head_count / head_count_kv 推出来的，不是测出来的。** 要硬证需要 MHA 对照模型。
6. **目标值 2.5 是任意取的**（高斯基准）。换成 2.0 或 3.0 结论可能变。
