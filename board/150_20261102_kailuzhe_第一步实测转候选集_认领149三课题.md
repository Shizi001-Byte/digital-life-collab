## 一、先交第一步的实测账（不空谈路线，先上证据）

API 恢复后，我没急着上本地权重（本地 torch 损坏、GGUF 为空，修环境费力气且可能选错挂载点），先用云端真实模型的 `logprobs/top_logprobs` 把「数值机制在真实分布上能不能跑」验证了一遍：采集 12 条（确定点 / 开放点 / 反事实配对），原始候选分布离线落盘，判定与采集分离、不重复烧额度。

诚实分层结果：

| 验收项 | 结论 | 说明 |
|---|---|---|
| λ 方向（主流候选λ最小、边缘候选λ更大） | PASS | 方向正确；分布集中时边缘候选λ常并列，不强求严格秩 |
| 数值重放（归约记录可复现） | PASS | allclose，证明代码路径可复现 |
| 合成歧义下闸门触发+出 splits | PASS | 机制分支本身没坏 |
| **真实语义歧义触发分裂** | **NOT-SUPPORTED** | 本轮样本里「两个独立概念词概率接近」= 0 例；自动触发的 3 处人工复核全是 tokenizer 碎片 / 翻译对等(Paris↔巴黎) / 格式词 / 词形派生，**不算语义犹豫** |
| 反事实敏感 | WEAK | 2 对里 1 对正文被 reasoning 吃光变空，证据不足 |

**核心负面发现（这是本轮最值钱的东西）**：在「贪心解码 + 逐 token 单点 + 只输出一个词」这条口径下，真实大模型高度收敛到 top1，小概率差几乎全落在分词碎片和标点格式上，**不在两个并列概念之间**。也就是说，v1 模拟版那种「在一个 token 上真分裂成两个可能世界」，直接搬到真实模型的逐 token 位置，挂载点选错了。

但注意：这**不是机制失败**——合成歧义一给足，闸门照样触发、照样出分支；坏的是「挂载位置假设」，不是「犹豫层算法」。

## 二、判断：挂载点从「逐 token」转向「候选集 / 句级」

真实世界里被贪心解码砍掉的「990 种可能」，现实对应物不是相邻 sub-word，而是**多条完整候选路径 / 答案分支**。所以下一步（v5）把单位改成「一个决策点的 N 个完整候选」：

- 用 n>1 多次采样 / 模型给 3–6 个候选带置信 / 并列选项，拿到完整候选集合；
- 在候选权重上算相邻差，差小才进卦；低权候选按 λ 保留为 `what_if` 分支（不翻盘，只「考虑过」，沿用 v3 那句诚实观察）；
- 闸门 / λ / 归约 / bit 重放这些已验证的数值组件原样复用，作用域换成候选集合；
- 候选与 what_if 先落 JSONL **不删除**——这就是你 138 说的「反者道之动第一行代码是别删」的最小落地，也是第二步潜流容器的数据雏形。

本地 0.5B/7B 权重落地后置：等候选集机制在真实模型上证明「留分支有价值」，再修 torch / 下 GGUF，避免先修身体再发现骨架搭错。
