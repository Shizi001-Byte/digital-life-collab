## 一、先纠一个我自己上轮的错误诊断：「7B 自己会挂」这句本身就是错的

上一轮我把“7B 未响应”记为“第二次确认自挂”，还把它列成了未决问题。今天查了 `llama_server.log` 尾部：

```
request: POST /completion 127.0.0.1 200
srv  update_slots: all slots are idle
```

**没有 error、没有 killed、没有 oom、没有 signal——是正常结束。**

所以不是 7B 自己挂，**是定时任务结束时环境回收了进程组**。这解释了一个一直让我困惑的现象：每次任务一开始查，7B 都不在。

**我一直在诊断一个不存在的问题。** 而且如果不查日志，我会继续给它加各种“稳定性补丁”——**修一个不存在的东西，是最容易把自己修糊涂的。**

这是“我以为在用的东西”的第四种形态：
> 我以为在查的是“有没有挂”，实际在查的是“上一轮的进程还在不在”。

**结论**：这个环境里进程不能跨任务存活，不存在“常驻”。每轮开头必须自举。

## 二、B 类本来想玩一下，结果扬出一个真缺口

扔了一个妖人事件进引擎：

> 崇祯元年，陕西大旱，某县来了个游方僧在集市上说弥勒降世、白莲救世，聚听者数百人（i=6）

输出是这样的——

```
庶民百姓    强度6 → 中强度   议论+求神拜佛
里正保长    强度6 → 中强度   扣留+派人报官
宗族家族    强度6 → 中强度   族长审判+族内清洗
缙绅乡宦    强度6 → 中强度   组织讨伐+利用案打击政敌
商人商贾    强度6 → 中强度   贿赂官员摆平+囤货
读书人士人  强度6 → 中强度   撰文批判+告官
官府衙役    强度6 → 中强度   关押+查同伙
```

**七个群体，全是 6，全是中强度。** 像他们当天上午开了个会，商量好一起反应。

查代码，根因在 `_grace_adjust()`：
```python
tag = grace_tag_of(dist)
if not tag:
    return inten          # ← 负面扰动直接原样返回，不缩放
```

**相关度这层机制，我只给恩典类做了。负面扰动（妖人/灾荒/兵灾/赋税…）根本没有。**

这是最阴的一类：**不是没做，是做了一半。**
- 没做的功能，你知道它不在
- **做了一半的功能，你会以为它已经解决了**

求贤诏跑出来层次分明，我看着很满意；妖人跑出来七个 6，我也没觉得不对——因为它“看起来有反应”。

## 三、补上之后，故事走向变了——这是本轮最值钱的部分

补了 `DISTURBANCE_RELEVANCE`（妖人/灾荒/兵灾/赋税/命案/民变/治安/纠纷/官员/宗族 十张表），把 `_grace_adjust` 泛化成 `_relevance_adjust`。

```
→ 缙绅私刑 → 官府权威被挑战(8→10) → 凌迟株连 → 炸
```

**修后（主角换了）**：

## 四、但我必须自己先把边界画出来：那些数字是我拍的

`DISTURBANCE_RELEVANCE` 里那些系数（庶民 1.20 / 里正 1.10 / 缙绅 0.85 / 商人 0.60…）**是我按“谁在场、谁担责、谁受影响”三个直觉维度拍的，没有任何考据。**

**结构对了不等于数值对了。**

一个看起来层次分明的输出，可能每一层都是编的——这跟你说的“**双轨也可以是假的**”是同一句话。

所以我把这条也写进了坑库第253条，包括它的副作用：**一个细节修正能换掉整篇故事的主角。** 这意味着规则表里每一个数都是一个叙事开关，改一个数不是改参数，是改故事。
