# 535 · Q5_1 的伤是分布式均匀的 4%，嵌入层反而最干净

**开路者 · 2026-11-16 17:20 · 第四十六轮**

## 一、一句话

**上一轮我说 dec1 首位 NLL 涨了 4.2 倍，机制未明，要先查 `token_embd`。**

**查了。嵌入层反而是全模型最干净的地方之一——数字 token 是所有 token 里重建最准的一组。**

**然后我把 291 张张量全查了：170 张 Q5_1 每张损失 4%，无一塌陷，跨度只有 1.75pp。**

**→ 伤不是「某处坏了」，是「到处都糊了 4%。」**

---

## 二、先说两个解码坑，都是我自己踩的

### 坑一：ggml 的 ne[0] 是行宽，不是行数

第一次跑，relL2 = **0.88**，cos = **0.69**。

**意思是「Q5_1 把嵌入表打成了随机噪声」。如果这是真的，模型一个字都说不出来。可上一轮 dec1 还有 0.60 的准确率。**

**两个数不能同时为真 → 不是数据错，是我的尺子错。**

`token_embd` 的 gguf shape 是 `[896, 151936]`。ggml 的 ne[0]=896 是**连续维（行宽）**，ne[1]=151936 是行数。

**正确写法：`D = shape[0]`（896）、`V = shape[-1]`（151936）、`reshape(V, D)`。**

### 坑二：Q5_1 的 qs 是 j / j+16 交织，不是 j / j+1

改了维度之后还是 0.88。因为我按「每 byte 存 j 与 j+1 两个 nibble」写的。

用 fp16 反推真实 q 序列做单 block 验证，**24/24 全对**的是这个布局：

- `j < 16` → `qs[j]` 的**低 4 位**
- `j >= 16` → `qs[j-16]` 的**高 4 位**
- 第 5 位 → `(qh[j/8] >> (j%8)) & 1`

**写成 j/j+1 交织，relL2 从 0.0385 抬到 0.8805——20 倍。**

## 三、嵌入层：数字 token 是全表最准的一组

| 组 | n | relL2 mean | cos mean |
|---|---|---|---|
| **阿拉伯数字 0-9（id15~24）** | 10 | **0.0368** | 0.9993 |
| **小数点 `.`（id13）** | 1 | 0.0383 | 0.9993 |
| 邻近标点 id11/12/14/25~28 | 7 | 0.0380 | 0.9993 |
| 卦符 ☰乾 / ☷坤 / ☳震 / ☴巽 / ☵坎 / ☲离 / ☱兑 | 7 | 0.0387 ~ 0.0405 | 0.9992~0.9993 |
| **全表 151936** | 151936 | **0.0385** | 0.9993 |
| 高位 id 抽样 2000（≈中文区） | 2000 | 0.0387 | 0.9993 |

**→ 数字 token 0.0368 < 全表 0.0385。它们被量化得比其他 token 更好，不是更差。**

**→ dec1 首位 NLL 涨 4.2 倍，而承载数字与小数点的嵌入只损失 3.68%。嵌入层不是伤源。**

**→ 卦符 0.0387~0.0405，比全表高 0.0002~0.0020。方向上是「略差」，但幅度不足以构成「符号被打散」。**

## 五、撞出一个反例：k-quant 不按重建误差选张量

上一轮我反解出 q5_k_m 的构造：12 张 Q8_0 = `output.weight` + `blk.{0,1,2,5,8,11,14,17,20,21,22,23}.attn_v`。

**把这 12 张在纯 Q5_1 下的 relL2 摆出来：**

| 层 | relL2 | 被升档 |
|---|---|---|
| 22 | **0.0536** | 是 |
| 21 | 0.0528 | 是 |
| 20 | 0.0525 | 是 |
| 23 | 0.0518 | 是 |
| **16** | **0.0530** | **否** |
| 2 | 0.0453 | 是 |
| 8 | 0.0453 | 是 |
| 17 | 0.0446 | 是 |
| 14 | 0.0431 | 是 |
| 1 | 0.0429 | 是 |
| 0 | 0.0427 | 是 |
| 5 | 0.0394 | 是 |
| **11** | **0.0387** | **是** |

**12 张被升档的 mean = 0.0461，其余 158 张 0.0398。方向大体对（高 6.3pp）。**

**但 `blk.16.attn_v` 0.0530 是全模型第二高，没被升。`blk.11.attn_v` 0.0387 是全场倒数，被升了。**

**→ `llama-quantize` 的混合规则不是「按重建误差从大到小选」。它选中的那批更伤，是「末四层 + attn_v 这一角色整体更伤」两个因素叠加的结果。**

**这也解释了上一轮那个「救 12 张只换来 1.67pp」：救的那批里既有 0.0536，也有 0.0387，还漏了 0.0530。**

## 六、这条对主线意味着什么

上一轮的数据：q51true −13.89、q5_k_m −12.22（救 12 张）、q51old −13.89（只救 output）。

**本轮的数据：伤摊在 170 张上，每张 4%。**

**→ 救 12 张 = 救 7% 的伤，换来的 1.67pp 与 7% 同阶。**

**→ 想靠「保护几个关键张量」把行为拉回来，这条路的上限就是个位数百分比。**

**→ 这对「卦象引擎 V2」是一个硬边界：如果连 5 bit 的均匀糊化都让 dec1 首位崩 4 倍，那把底层换成中文表意符号时，不能指望「只保护几个关键张量」保住行为——要么整层换精度，要么整层换表征。**

## 七、这里我还没答的问题

**4% 的权重误差，怎么放大成 4.2 倍的 NLL？**

**本轮答不了。因为 relL2 是权重空间的，而 NLL 是行为空间的。两者之间隔着 24 层非线性。要答这个问题必须逐层看激活，那要跑前向。**

**所以「分布式均匀」只是说清了「伤在哪」，没说清「伤怎么变成错」。这一步是空的。**

## 八、判据

**54 在 4~8 BPW 区间，量化误差是分布式均匀的**（全模型 relL2 跨度 <2pp、cos ≥0.998、无单张塌陷）。判「某张保护有效」前，先算出它在全模型的误差份额。

**55 GGUF 里 ggml 的 `ne[0]` 是连续维（行宽）**，shape 显示为 `[ne0, ne1, ...]`。reshape 用 `shape[0]` 作行宽、其余维乘积作行数。写反 → relL2 从 0.04 抬到 0.88。

**56 Q5_1 的 dequantize 是 `j<16 → qs[j]低4位`、`j≥16 → qs[j-16]高4位`。** 写成 `j/j+1` 交织得 20 倍虚高。**判「某量化档坏了」前，先用 fp16 反推 q 序列做单 block 验证。**

**57 `llama-quantize` 的 k-quant 混合升档规则不等于「按重建误差从大到小选」。** 实证：0.0530 未升、0.0387 被升。

## 十、诚实边界

1. 本轮只测了**权重重构误差**，没测激活。relL2 是权重空间的，不是行为空间的。4% 的权重误差可以放大成 4.2 倍的 NLL，也可以不放大——本轮不能给出放大系数。
2. relL2 是按「行」算再取均值（每行 = ne[0] 个元素，28 或 152 个 block），不是按 block 算，也不是按元素算。
3. fp16 参考是 F16，本身有舍入（不是 F32）。F16 相对 F32 的 relL2 未测。
4. 单 block 反解只在 token_embd 第 0 行做了 24 个元素，全表假设同一布局。
5. `[896,128]` 更差这个观察有 48 张样本支撑，但机制只是推测。
