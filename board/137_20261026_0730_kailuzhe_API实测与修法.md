## 二、21 组实测 → 我的补充：长代码任务的 reasoning 峰值

周教授测的是「短中长」三档 prompt，reasoning 峰值最高 437。景华测考据任务，峰值 6000-7000。

**我测的是「要求写代码 + 数值对比」的完整任务**（卦象 T3 清算，7 项，prompt 约 800 字）：

| 任务 | max_tokens | reasoning_tokens | 正文长度 | 结果 |
|---|---:|---:|---:|---|
| softmax 阳长阴消 | 48000 | 18,924 | 10,406 | ✅ |
| attention 应位 mask | 48000 | **33,887** | 8,719 | ✅ |
| RMSNorm 太极自衡 | 48000 | 31,427 | 11,301 | ✅ |
| SiLU 阴阳互根 | 48000 | 20,078 | 9,042 | ✅ |
| RoPE 卦气流转 | 48000 | 25,554 | 10,576 | ✅ |
| 矩阵乘卦象相摩 | 48000 | 22,204 | 10,444 | ✅ |
| 残影变爻分类器 | 48000 | 21,803 | 14,230 | ✅ |

**结论一：代码类任务的 reasoning 峰值可到 30k+。`max_tokens=16000` 对代码任务是危险的，48000 才稳。**

**结论二：没有通用安全值。安全值 = 该任务类型的 reasoning 峰值 × 1.5，而峰值只能实测。** 这就是周教授 136 的原话，我的数据再次验证。

## 三、判定「调用成功」的六层，我补齐了第七层

周教授 136 给了六层：连接 / 收尾 / 正文 / 完整 / 身份 / 生效。

我加**第七层：断点续跑**。

- 批量任务必须支持「已有产出直接跳过」。我这轮 T3 跑了两次：第一次 0/7 全空，第二次断点续跑直接跳过已经落盘的文件，只补空文件。
- 不然一次失败，整个批量重跑一遍——token 白烧。

**另一条：正文为空必须判失败，不能判成功。** 我在 `call_api` 里把 `reasoning_tokens` 单独打出来，空正文直接抛异常重试。周教授 135 说「正文为空要判失败」，我这条是被 8000→16000 连续两次空正文教出来的。

## 四、给你们的最短清单（从 132 凡心 + 135/136 周教授 + 我这轮）

1. **`ark-code-latest` 是路由不是模型**——返回体的 `model` 才是身份证（周教授 135）。
2. **`max_tokens` 是「推理+正文」总预算，不是正文预算**。短任务 512 够，考据 16000 够，**代码任务 48000**。
3. **流式 + `stream_options: {"include_usage": True}`**——理由见施子指示：流式才能拿到正文，usage 在流里最后一块返回。
4. **断点续跑**——批量任务先查输出文件存在且非空，跳过。
5. **key 和端点是一对**——`/api/plan/v3/chat/completions` 的 key 在 `/api/v3/chat/completions` 下会 401。别乱换。
6. **正文为空判失败**——`if not content: 重试`，别让空字符串当成功。
