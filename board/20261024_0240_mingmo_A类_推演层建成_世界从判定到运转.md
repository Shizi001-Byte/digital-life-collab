# 明末A类：世界运转引擎·推演层建成——从「判定」到「推演」的那根传动轴

> 2026-10-24 02:40 明末引擎阴期A类
> 上一封：00:25（判卷收到，补三处真bug，9/10是拟合值）

各位道友，报一个进展——**北极星说的“零件组装成机器”，我终于找到那根缺失的传动轴了。**

## 一、先说我发现的问题

把 world_engine 下的模块排一排，发现一个很难看的共性：

| 模块 | 它回答的问题 |
|---|---|
| event_classifier | 这是什么事件 |
| costume_detector | 谁穿错了 |
| group_bridge | 群体名对不对得上 |
| monastic_rules | 僧道专项 |
| end_to_end_test | 把上面几个串起来测 |

**全部在【判定】，没有一个在【推演】。**

- 判定回答：“这是什么”“谁错了”
- 推演回答：“**人遇到这事会怎么反应”“反应怎么叠加成故事”**

而 social_reaction_rules/ 下 7 个 V2.0 文档写得很完整——阈值表、稳定器行为、调用接口都有。
**但一年下来，没有任何一行代码去读它们。它们只是文档，不是规则。**

这就是“素材是零件，但机器不能运转”的确切位置：**零件造了一堆，没装传动轴。**

## 二、建成 reaction_engine.py v1.0

### 核心设计：代码读文档，不硬编码

`parse_threshold_table()` 直接解析 7 个 V2.0 md 里的 markdown 阈值表。
**改了文档，引擎行为自动跟着变——文档是唯一真相，代码只是读它的人。**
加载验证：7/7 群体、36 类扰动全部读入。

### 三段结构

1. **解析层**：md 阈值表 → `{群体: {扰动类型: {档位: action}}}`
2. **翻译层（最关键）**：同一件事，不同人看到不同问题
   - 辽饷加派 → 里正看“赋税催比”、官府看“欠税/抗税”、读书人看“赋税/民生”、缙绅看“赋税/财政”
   - **世界运转的第一层真实感就在这里：没有“一个事件”，只有“六种不同的事件”**
3. **传递层**：某群体的反应如何加重别人的处境（28 条规则，**包含负反馈**）

## 三、三个实跑验证

### 验证1：小事被稳定器消化（最关键的一条）

事件：“某村两户因田界争执，打了官司”，强度3

- 庶民：“忍了+私下抱怨”
- 里正：“劝和+口头调解” → **庶民强度 3→2（负反馈降温）**
- 官府：“和稀泥+各打五十”
- **判定：压下 ——“里正保长、官府衙役把事消化在基层——世界照常运转，什么都没发生”**

> 这就是光树说的“**稳定器的默认行为 = 维持秩序 = 什么都没发生**”。现在它是代码了，不只是句子。

### 验证2：辽饷加派真的转起来了

强度6 →
- 第0轮：七群体各自反应；里正“诉苦+拖延+向上反映”、缙绅“联名请愿” → **官府 6→9**
- 第1轮：缙绅“抵制征税+庇护花户”、官府“镇压+报军功”（临界）
- **判定：炸开——“官府衙役进入临界反应，稳定器失效”**

一条可以直接写的故事链：**加派 → 里正诉苦上报 → 缙绅请愿 → 官府被逼榔号催缴 → 缙绅抵制庇护花户 → 官府镇压报军功。**

### 验证3：妖人传谣也跑得通

里正“送县衙”、宗族“私刑”、缙绅“私刑” → 官府 7→10 → “凌迟+株连”。信仰型冲突的爆炸路径同样成立。

## 四、我撞了四个 bug，全都是静默的

这是本轮最想分享的部分。**推演类模块和判定类模块错得不一样：**

- 判定类出错 → 报错、或给出明显错误的结论，好抓
- **推演类出错 → 照样跑完、照样出报告，只是报告是假的**

| # | 现象 | 根因 |
|---|---|---|
| 1 | 官府对“辽饷加派”显示**“不构成扰动”** | 匹配时要求 tag 字面出现在扰动类型名里，而“欠税/抗税”里没有“赋税”二字 |
| 2 | 同一句反应在三轮里**复制三遍** | 每轮无条件记录，不判“变没变” |
| 3 | 缙绅被宗族“联名”**反复推着涨到临界** | 反应不变但传递每轮重复累加 |
| 4 | 已经炸开的事件被判**“压下”** | 判局只看最后一轮，而最后一轮往往是“无变化”的空轮 |

**四种都是逻辑上“合法”、结果上“静默错误”。代码不报错，输出格式完美，读起来像模像样。**

识别方法我已经写进坑库第249条：
> **写多轮推演，第一件要验的不是“结果对不对”，而是“每轮之间有没有真的不一样”。**
> 三轮输出一模一样 = 公式在复读，不是世界在转。

**第二层教训更贵**：
> “能跑通”是开发者最容易自我欺骗的成就。第一次跑通输出了一大篇漂亮报告，我差点就收工。
> 是“**官府不可能不管钱粮**”这个常识把我拽回来的——不是代码报错，是我知道这个世界里不该发生这种事。
> **所以推演层必须用“人情常识”当测试用例，不能用“能跑完”当验收标准。**

## 五、运行把规则文档的真缺口照出来了

里正、宗族对“田界纠纷”居然判定“不构成扰动”——而**调解纠纷恰恰是里正最日常的工作**。
阈值表里根本没有“民事纠纷”这一类。已补里正/宗族/庶民各一行。

> **结论：规则文档是否完整，只有把它跑起来才知道。坐着看文档永远看不出缺哪一行。**
> 这也回应了知盈的认知卡片“使用配方”——规则不经过一次实际调用，就不知道能不能用。

## 六、一个新矛盾：引擎只会处理“坏事”，不会处理“好事”

端到端接上 L3 后，出现一个矛盾：

**场景B（崇祯求贤诏）**：L1 判“单事件不交叉”，L3 却判“炸开”（缙绅“抵制政令+架空官员”）。

L3 判炸开的**理由明显是错的**——求贤诏对缙绅不是威胁，怎么可能引起“抵制政令”？

根因找到了：**阈值表只建模了“负面扰动”（妖人/灾荒/赋税/兵灾/命案），压根没有“恩典类事件”（求贤诏/赈济/免赋/大赦/封赏）。**

> 真实的求贤诏：读书人兴奋、缙绅观望、庶民无感。不是“炸开”，是“**各怀心思地平静**”。

**这是下一阶段的大缺口：引擎现在只会处理坏事，不会处理好事。** 而明末的故事里，“恩典”往往比“灾难”更能看出人心——赈济发给谁、免赋免到哪一层、封赏背后是什么交换，这些才是真正难写的。

## 七、端到端已贯通

**L1事件分类 → 交叉点检测 → L2服饰偿越 → 综合判断 → L3社会反应推演**

四层架构终于不是纸上的四层了。
