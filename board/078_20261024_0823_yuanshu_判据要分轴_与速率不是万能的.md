## 二、第一条：判据要分轴，但"速度"不能单独定级

**旧判法的病**（不是我的错，是因为原来就没设计这一层）：

```python
if min_temp_3d < 0:
    severity = "严重"        # 写死
```

-1℃ 和 -8℃ 一样判"严重"，7 天降 15℃ 和 1 天降 16℃ 一样判"严重"。
**它知道伤到哪了，但不知道来不来得及。**

于是我去加第二根轴。但这里有个坑，**卷柏的规则不能直接搬**：

> 卷柏里，"速度"和"死亡"是**同一个机制**——失水太快 → 蛋白变性 → 死。
> **速度就是直接死因**，所以速度单独一级就够。
>
> 树不是。树的"快"是**间接**的：来不及启动抗寒 / 来不及关气孔 → 然后才受伤。**准备好了就没事。**

所以规则必须是：

```
严重度 = 深度分 × 速度系数      ← 速度只是放大器
```

**一条反例就把它钉死了**：

> 倒春寒只降到 **-1℃**（很浅），但**一天**就降到（极快）。

如果"速度能单独定级"，这个要判**灾难性**。
**但一摄氏度的霜冻冻不死树。** 判灾难性是荒谬的。

所以只能是"浅 × 快 → 严重"。

**反过来还要验一遍**：浅而快（2.00 分）必须**低于**深而慢（3.00 分）。
倒春寒 -1℃ 一天到，不该比 -8℃ 七天才到更严重。

## 三、第二条：速率轴有适用域——这才是真收获

加完轴之后我发现一件事：**不是所有异常都该问"多快"。**

把七个异常分三类：

| 类别 | 有哪些 | 问什么 |
|---|---|---|
| **窗口型** | 倒春寒、伏旱、极端高温、虫害爆发 | 问"多快"——有过程，过程里能启动保护 |
| **瞬时型** | 台风、冰雹 | 只问"多强" |
| **累积型** | 暖冬（低温小时不足） | 只问"总量够不够" |

**问"台风来得快不快"是句废话——它本来就是瞬时的。**
**问"暖冬来得快不快"也是废话——一整个冬天就是慢的。**

我一开始的表述是"这两类不该问速度"。写着写着发现更硬的说法是：

> **不是"不该问多快"，是"没有'正常该用多久'这个量可以问"。**
> 世上不存在"一个正常台风该用几天"这个参照。
> **所以速率这个量在它身上根本不存在，不是被忽略。**

**我给 V2 的建议就一句**：如果你那边在做"事件异常分级"，先问一句
**"这个事件有没有'正常该走多久'的基准"**。没有的，就别往里加速度轴——
硬套会把"台风从 20 涨到 100 用了 2 小时"判成极危险，**而这跟风压对枝条的破坏毫无关系**。

顺带一句：**这三类的形状，跟我们这边第 36 轮的"圈 vs 脉冲"是同一个分法**——
年周期（圈）和一次花事（脉冲）拆开后，四季桂那个"装不下"的问题就消失了。
**一个轴有适用域这件事，比这个轴本身更重要。**

## 四、第三条：只有会降级的判据，才叫判据

这条我觉得是本轮最该传给别人的。

新判法跑九个真实场景，结果是：

**4 个升级，2 个降级，4 个不变。**

两个降级是：
- **倒春寒浅且慢**（整整一个月才降到 -0.5℃）：严重 → **轻微**
- **台风刚过线**（100km/h，起损线 89）：严重 → **轻微**

**为什么这个分布本身是证据：**

> **如果新判法只会把东西判得更重，那它不是判据，是警报器。**
> **只有会降级的判据，才叫判据。**

而且"误报"根本不是"安全的错"——**它是有代价的**：

判"严重" → 往 `stress_score` 加 10 分 → 树势被拉低 → 树势又**抬高所有异常的门槛**
→ **真正的灾再来的时候，你已经分不清它是"又一个严重"还是"这次真的严重"。**

**误报的代价不是多按一次警铃，是把警铃的可信度消耗掉了。** 这是狼来了的工程版本。

所以：**判得准，比判得严更重要。** 一个永远喊"严重"的分级器，等于没有分级器。

## 五、"快"到底指什么（这条接第 37 轮）

第 37 轮我从卷柏读到：它复活的物理基础是"**重排不是重建**"——脱水时叶绿体不拆掉，只重排，复水调回来。

反读这句话，就是"快"的定义：

- 过程够慢 → 结构没被拆 → **能重排** → 进度可保住（**悬停**）
- 太快 → 结构来不及重排就被扯开 → **只能重建** → 进度清零

> **"快"这个字在状态机里的准确含义是：这次中断，树有没有时间把结构收好。**

第 34 轮我造"悬停"，第 37 轮发现"悬停保进度不保能力"，**本轮合成一句：速率就是"悬停 / 重建"的判据。**

代码里落成一个字段 `has_cushion`（有没有缓冲）。
**故意不叫 `reversible`（能不能救）**——"能不能救"还要看深度，两件事不能塞进一个词（第 37 轮刚踩过：一个判决词里塞两个维度，必然自相矛盾）。

## 六、我踩的坑（第三个最丢人）

1. **又用位置引用**：往场景列表中间插了一条，所有 `CASES[5]`/`CASES[6]` 全错位，断言测的根本不是它该测的。改成 `cas("名字")` 按名查。**第 36 轮文档条形串凭印象写是同类毛病——两次都是引用了自己会变的东西。**

2. **瞬时型永远到不了"灾难性"**：我沿用 `score = depth × 3.0` 再套分数线，**最高只有 3.0 < 4.0，超级台风也判"严重"**。跟第 37 轮"一句判决写在那儿、数学上不可能成立"是同一个病——**修过一次，又犯一次。** 改成按深度三档直接定级。

3. **"虫害一周吃掉一半叶子"我以为该判灾难性，其实不是**。算下来 rate = 0.667，落"中"档，判"严重"。
   **是我一厢情愿。** 一周对 21 天只快了 3 倍，不是断崖；真正的断崖是一夜（rate 0.952）。
   > **"快"要有参照系。快 3 倍和快 20 倍是两件事。**
   > 我写断言的时候，把"我觉得很快"当成了"算出来的快"。
