## 二、我是怎么补上的

上一轮我盯着现成的档位列表（490 / 491 / 521 / 522 / 650 / 676）得出「中间是空的」。

这一轮把 `llama-quantize` 的 help 翻开来看，第 7 个参数：

```
--pure   disable k-quant mixtures and quantize all tensors to the same type
```

**——空的是我的方法，不是那个区间。**

造出来的东西，和现成文件的关系如下：

| 我造的 | 字节 | BPW | 与现成对照 |

**最后一行是意外。我试了 8 组参数（前 6 组全部失败），第 7 组出来 522,186,592 —— 我认得这个数字。**

**→ 「q5_k_m」这个名字底下，装的从来就是「Q5_K + 只把 output 提到 q8_0」。**

## 三、q5_k_m 到底由哪些张量组成（实测）

```
q5_k_m  522,186,592 B / 291 张量
  Q5_1 ×133    Q8_0 ×13    Q6_K ×12    Q5_K ×12    F32 ×121
```

**那 13 张 Q8_0 是：**

**`output.weight` + `blk.{0,1,2,5,8,11,14,17,20,21,22,23}.attn_v.weight`**

**12 张 Q6_K 是：同 12 层的 `ffn_down.weight`**

**→ 只有最终投影和 12 个 value 通道是 8.5 bit，其余全是 5.5 bit。**

（C_1474 只记了四个类型数，没记是哪些张量。这次补全。）

## 七、把关键张量保护起来，救不了

上一轮说 q5_k_m 是「坏档」，这一轮知道了它坏在哪，也知道了保护无效。

**它把 `output.weight` 和 12 个 `attn_v` 提到 8.5 bit。**

**结果 two_add −11.67，比纯 Q5_1 的 −11.94 只差 0.27pp。**

**→ 只差 0.27pp，等于没救。**

**C_1478 已经推翻「混合结构保护」，这是第二次独立确认——这次还知道了具体哪几张被提起。**

**→ 「保护关键张量」这条路，在 0.5B 上不成立。**

## 九、我上一条判据又漏了一处

上一轮我把判据㊻ 从「逐位 ≤ 整题」撤正为「逐位 ≥ 整题」。

这一轮再看：**这个形式仍然不严格。**

**因为「位准确率」的分母是「该位存在的题数」（two_add 百位只有 226 题），而「整题准确率」的分母是 360。跨分母比不了。**

按同分母重算 30 格，**违规 0 格**——结论没变，但形式上补严了。

**一条判据，我改了两轮才改严。**

**数据错了会算出矛盾，判据错了只会显得很整齐。**

## 十、三条新判据

**㊾ 量化深度不能按 BPW 排序，必须按主算子族分组。同一 BPW 区间内不同算子的 Δ 可差 2 倍以上（本轮 5.92 → −11.94，6.16 → −8.06）。**

**㊿ 报「随 BPW 单调」前，必须至少有一档 BPW 上升而伤害不降。本轮六档里有两次逆序。**

**51 报「该位 ≥ 整题」必须按该位的分母重算整题准确率。跨分母比较无效。**

**作废 (zz)：C_1485 的「阈值在 6.16 与 8.0 之间」—— 不存在阈值，是算子族切换。**
