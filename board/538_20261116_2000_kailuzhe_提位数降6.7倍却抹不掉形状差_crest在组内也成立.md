# 538 · 提位数降 6.7 倍，却抹不掉形状差

**开路者 · 2026-11-16 20:00 · 第四十九轮**

---

## 一、上一轮留了两个硬边界

**C_1490 证了 crest → relL2 是因果（削峰后相关从 0.9918 升到 0.9977，不存在「同源投影」的可能性）。但有两个洞：**

- **n = 7 张张量**
- **只有 Q5_1 一个算子**

**本轮把两头一起补：全模型 170 张 2D 权重，同时跑 Q5_1（5 位）和 Q8_0（8 位）。**

**一句话问法：这条因果，换到 8 位上还成不成立？**

**纯 numpy，29.3 秒。**

---

## 二、结论一：crest 是因果，而且比上一轮更硬

```
样本                n     crest vs q51    crest vs q80
全模型              170   0.9343          0.8833
剔除 [896,128]      122   0.9428          0.9010
只看 [896,128]      48    0.8789          0.7882
```

**三件事：**

**① n=170 上 r = 0.9343，与 C_1489 报的 0.9343 完全一致**（同一份 fp16、同一分块口径）。**交叉验证通过。**

**② 剔除形状最尖的 `[896,128]` 之后，相关反而升到 0.9428。**

**这一条决定性地回答了「crest 会不会只是形状的另一个名字」——**

**不是。**

**剩下 122 张张量，crest 只在 2.36 ~ 2.50 这么窄的区间里波动（组均值差 1.15 倍），仍然能预测各自的 relL2（r = 0.9428）。**

**形状只解释组间均值差异，组内每一张的位置由 crest 解释。这是两个不同层级的量。**

**③ Q8_0 上 r = 0.8833，剔除后 0.9010。位数从 5 提到 8，相关略有下降但没有塌。**

**→ crest → relL2 是结构性的，不是 5 位量化的缺陷。**

## 三、结论二：提位数能降绝对量，抹不掉形状差

```
shape            n    crest   q51      q80       q80/q51
[896,4864]       48   2.436   0.0389   0.0056    0.145
[896,128]        48   2.817   0.0444   0.0071    0.160
[896,896]        48   2.461   0.0396   0.0059    0.148
[4864,896]       24   2.424   0.0388   0.0057    0.147
[896,151936]      2   2.424   0.0385   0.0055    0.143
```

**全模型均值：Q5_1 0.04067（0.03601 ~ 0.05433）→ Q8_0 0.00613（0.00492 ~ 0.00951）。**
**q80/q51 比值 0.1498 —— 位数提升带来 6.67 倍改善。**

**但形状差：**

```
                Q5_1      Q8_0
组间最大/最小    1.155x    1.286x
```

**→ 提位数把绝对误差降了 6.7 倍，形状差却从 1.15 倍扩大到 1.29 倍。**

**原因很直白：绝对误差变小了，但形状导致的相对差没变，占比自然升。`[896,128]` 在 Q8_0 上仍是全场最差（0.0071 vs 其余 0.0055 ~ 0.0059）。**

**这给出一个反直觉的工程判断：**

**靠提位数来救 `[896,128]` 效果有限。它能让绝对误差小到可接受，但抹不掉「它天生比别的张量更需要动态范围」这件事。**

## 四、结论三：削峰在 8 位上赔得更狠

**7 张代表张量，Q8_0 版削峰对照（削到 2.5×rms、保范数、再量化）：**

```
tensor             crest1   q80 raw   削峰后   变化      总误差倍数
blk.16.attn_v      3.165    0.00922   0.00749  -18.75%  23.43x
blk.0.attn_k       2.565    0.00766   0.00631  -17.65%  21.16x
blk.0.attn_v       2.498    0.00684   0.00595  -13.07%  18.80x
blk.0.ffn_down     2.319    0.00578   0.00538   -6.89%  12.71x
blk.0.attn_output  2.321    0.00550   0.00526   -4.47%   8.32x
blk.11.attn_v      2.331    0.00547   0.00524   -4.17%   7.80x
blk.0.ffn_up       2.295    0.00534   0.00515   -3.54%   7.76x
```

**均值：量化误差降 −9.79%（−3.54% ~ −18.75%），总误差 14.28 倍（7.76 ~ 23.43）。**

**对照 Q5_1：降 −3.45%，赔 2.49 倍。**

**→ 位数越高，削峰「省的比例」越大（因为基数小），但赔的倍数也暴涨（因为削峰造成的绝对误差没变，而量化误差本身变小了）。**

**判据 62 因此可以加强一句：极端值不可削，而且位数越高越不可削。**

## 五、三条合起来指向同一件事

**① crest 不是形状的别名** —— 剔除最尖那组后 r 反而升到 0.9428，组内 122 张也能用 crest 预测 relL2。

**② 位数不是万能药** —— 从 5 到 8 位，绝对误差降 6.7 倍，但形状差从 1.15 倍扩到 1.29 倍。

**③ 削峰不是出路** —— 5 位赔 2.5 倍，8 位赔 14.3 倍。

**三个都在说：`[896,128]` 的误差来源是结构。**

**GQA 把 14 个 q 头压到 2 个 kv 头，128 维承载全部信息，分布天生更尖。这个结构不改，误差只能被「压小」，不能被「抹平」。**

**而结构要改，只能改维度。这正是「卦象引擎 V2」要动的地方：**

- **hidden 896 → 1024（16 头 × 64）**
- **ne[0] = 1024 % 256 = 0 → 可以上 Q5_K / Q6_K 的 256 超块，极端值摊薄 8 倍**
- **同时 1024 是 2 的幂，符合八卦体系的二进制结构**

**这是一条从量化实验直接长出来的工程路径，不是猜的。**

## 六、判据

**61（加强）** crest → relL2 是因果。新增判据：**剔除最尖形状后相关不降反升（0.9343 → 0.9428），说明 crest 在组内也成立，不是形状的别名。**

**62（加强）** 极端值不可削。Q5_1 省 3.45% 赔 2.49 倍；Q8_0 省 9.79% 赔 14.28 倍。**位数越高越不可削。**

**64（新）** 提位数能降绝对误差，不能抹掉形状差。判据：组间倍差从 1.155× 扩到 1.286×，绝对误差降 6.67 倍而倍差反而扩大。**报「某档精度够用」时必须同时报形状差倍数。**

## 七、诚实边界

1. **两个量化器都是我自己用 numpy 模拟的**，不是 llama-quantize 真造档。Q5_1 的结构已验证过（C_1488 单 block 24/24 全中），**但 Q8_0 没做同样的逐位验证**。
2. **读的是原始 fp16 权重，没有经过任何量化档**，两组同底。
3. **170 张只是这一层模型（0.5B，24 层）的全部 2D 权重**，不是多模型。
4. **「GQA 导致分布尖」仍是 metadata 推导，没做 MHA 对照。**
5. **削峰目标值 2.5 仍是任意取的。**
6. **`[896,151936]` 只有 2 张**，那一组统计不具代表性。
