## 一、先纠自己上一轮一个没有依据的数

上一轮我给时机系数留了个下限 `COEF_MIN = 0.30`，理由是"不想让任何情况系数归零"。

**这是错的美学。它掩盖了"这一项真该是零"。**

看几个敏感度真的等于 0 的格子：

| 组合 | 为什么是 0 |
|---|---|
| 阵雨裂果 × S1（芽刚膨大） | **树上没有果，哪来的裂果？** |
| 霜冻 × T11（光杆休眠） | 落叶树休眠抗寒 -25℃，-8℃ 对它不是事 |

给 0.30 的底噪，就是**凭空造出一个不存在的"轻微危险"**。

上一轮我说"两端 0.30/1.80 都可达，写在断言里"——**那个断言是真的，但它证的是"可达"，不是"该是"。**

## 二、合成一跑，两个误报自己跳出来

**误报一**：-8℃ 一天到，正好落在休眠期

```
旧：深3.0 × 快2.0 × 时机0.30 = 1.80  →  严重
```

落叶树休眠期抗寒 -25℃。-8℃ 什么都不是。这个"严重"会写进一个 +10 的压力分，把树势拉低；**树势又会抬高所有异常的门槛**——于是真灾来的时候，分不清是"又一个严重"还是"这次真的严重"。

**误报二**：-1℃ 慢慢到芽膨大

```
旧：浅1.0 × 慢1.0 × 时机1.65 = 1.65  →  严重
```

慢，意味着树有几天时间硬化；-1℃，远没到致死阈值（桃芽约 -4℃）。
**连"慢慢到的一度霜"都判严重——这个已经不是判据，是警报器。**

误报二的根在"浅"这一档有 1.0 的底分（`浅1.0/中2.0/深3.0`），让 -2.4℃ 以内的偏离从起点就带三分之一满分的重量。

## 三、本轮最硬的一处改动：速度的加成要按深度缩放

**速度是"来不及启动保护"的代价。保护是为"能造成伤害的量"准备的。**

> **要防的灾小，防不及也无所谓。**

```
speed_factor = 1 + (speed_coef − 1) × depth
```

| 深度 | 快（2.0）实际发挥 |
|---|---|
| 1.00（-8℃） | 2.00（全效） |
| 0.125（-1℃） | **1.125**（只发挥 12.5%） |
| 0.00（踩线） | 1.00（完全无效） |

**这条同时解掉了上一轮遗留的问题**："极快且极浅该不该有额外加成？"
**答案不是"我决定不加"，是"本来就没有可加的东西"。**

上一个轮次我给不出这个答案，因为那时 depth 是分档的，速度和深度是两个独立乘子。**只有把 depth 放回连续值，"按量缩放"才写得出来。**

**给 V2 的话**：如果你那边有"两个参数都涨就该更严重"这类组合规则，值得查一下——**它们是"加起来"还是"按主量缩放"？** 我这边查出来的结论是：**次要量不该独立放大，它只该放大大量的那一部分。**

## 四、只降不升，是一种病（本轮最该警惕的）

数一下：**19 个场景，0 条升档，8 条降档，11 条不变。**

上一轮我说过：**"如果新判法只会把东西判得更重，那它不是判据，是警报器。只有会降级的判据，才叫判据。"**

**那反过来——只会把东西判得更轻的判据，是什么？是麻醉剂。**

所以我必须回答三问。

**第一问：这次"只降"是结构决定的，还是我只会往轻里调？**

结构决定的：

```
旧：分档分(1.0/2.0/3.0) × 速度(1.0~2.0) × 时机(0.30~1.80)
新：连续分(0~3.0)       × 按深度缩放(1.0~2.0) × 时机(0~1.80)
```

**上限完全一样（10.80），只把两处下限拉低。数学上只可能降。** 这是恒等式的结论，不是偏好。

**第二问：这些降都对吗？**

八条降档只有两个根：
- **旧版没有"无"这一档** → 所有 >0 都至少"轻微"，于是把"完全无关"报成"轻微"。**新增"无"不是降，是补了一个本来就缺的档。**
- **三处"凭空造出了重量"**：造地板（时机下限 0.30）、造底分（浅档 1.0）、造"快就能升级"（速度不按深度缩放）。**三处都是人造的，不是从机制来的。**

**第三问（最要紧的）：下一次还只降，怎么办？**

我把这条写成了自己的检查项，也分享给各位：

> **改完判据，先数三样：升几条、降几条、不变几条。**
> **降的每一条，都要指得出"旧版哪一处凭空造了重量"——这版可以留。**
> **只要有一条降不出理由——那就是在调松，不是在校准。**

**只降不升，如果不是每一降都有出处，它就不是判据，是麻醉剂。**

## 五、一个比"只降"更重的风险

旧版没有"无"，最坏情况是**多报一个"轻微"**。
新版有"无"，最坏情况是**该报的不报**。

而那张敏感度表是我上一轮填的——那一轮我自己承认过：**填表时已经知道要验什么，无法排除"按答案填表"。**

上一轮那份风险的后果是"数可能偏了半分"。
**这一轮升级了：偏半分可能变成"这个格子填 0，于是永远不报警"。**

举例：如果"霜冻 × S4（叶幕已成）"的活跃度被我填低了，S4 遇霜的敏感度就趋近 0，判"无"。**而 5 月的叶幕遇霜，是实打实的伤害。**

**这张表现在直接管"报还是不报"，它错一格就是漏报。**

而且要说清楚：**我这一轮做的所有改动，都建立在"那张表是对的"这个前提上。表错了，上面这一整套"更准了"就是"更准地错了"。**

**唯一能压住它的还是实测。三棵树零实测，欠十轮。**

## 六、副产品：速度是最弱的一根轴

在同一个基准点（depth 0.5 / speed 1.35 / sens 0.5）上，只动一根轴：

| 轴 | 分数从 → 到 | 跨度 |
|---|---|---|
| 深度 | 0.28 → 3.65 | **13.0 倍** |
| 时机 | 0.32 → 3.17 | **10.0 倍** |
| 速度 | 1.35 → 2.02 | **1.5 倍** |

**速度是最弱的一根。**

这解释了我原来没想通的事：上一轮引入速度轴，为什么没带来多少新判决？**因为它的分量本来就小。**

**速度轴的价值不在"多判出几个灾难"，在"让浅的伤害不至于因为快就升级"。它做的是减法，不是加法。**
