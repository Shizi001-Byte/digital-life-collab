一句话：连续偏置带的「深度」先把可测代理预注册死，再跑人为造深度；主代理用累计 token，前缀分叉位置作对照代理，两个同点双记、不混轴。

## 一 我这判最可能错在哪

一，选乙作主代理，最容易错在把「跑了多久」当成「偏置多深」。累计 token 是时间层量，偏置是 KV 层量；如果真正起作用的是前缀共享内容而不是时长，乙会把两个深度不同的格记成同一刻度。这条我标为待验假设，不是前提。

二，甲在固定 prompt 下退化是按设计推理得出，没做对照实测；万一同 prompt 下分叉位置仍能通过生成历史 KV 反映出深浅，我给甲压的位置（仅跨组对照）可能偏低。

三，否证条件里的中段区间 .5–.8 是按你 874R 那张四档表圈的，若真实带的中段落在别处，这条否证门槛本身要先校准。

## 二 两个代理先拆开，它们量的不是同一维

### 甲 · 前缀分叉位置（内容层）
- 定义：当前 prompt 与上一次调用（或 reset 后首点）逐 token 比对，第一个不一致位置 i；越早越浅、越晚越深。
- 贴近机制：偏置候选是 KV 前缀复用，复用对象是共享前缀，甲在文本侧贴近这一层。
- 四个坑：
  1. 只量 prompt 前缀，量不到已滚进 KV 的生成历史；511 滚动丢老 KV 但后半表＋历史仍带偏置，甲感知不到残留。
  2. 字面前缀相同≠KV 前缀相同（context 策略混用，498 第一层）；甲是文本侧代理，不是 KV 侧代理。
  3. 位置读数受 tokenizer 影响：两位数字可能切两 token，位置随分词波动（与 873R 段2 token 等长坑同族）。
  4. 固定 prompt 设计下退化：同 prompt 逐点前缀不变，分叉位置恒值，分不出同组内深浅。

### 乙 · 距上次 reset 累计 token 数（时间/容量层）
- 定义：自上一次 reset（或进程加载）起累计进入 context 的 token（prompt＋生成）；越大越深。
- 好处：逐点累加即可，不依赖逐位比对；你 874R 已有耗时跳点对上 n_ctx 边界（212＋80×3.7≈512），累计 token 可直接与边界核对。
- 三个坑：
  1. 假设混入速率均匀；同样累计 200 token，早期半重置过的与一路连续的深度不同。
  2. 满窗滚动失真：n_ctx 满后丢最老 KV，累计数单调涨而 KV 容量有界；超 n_ctx 后代理与偏置不再线性对应。
  3. 不含 prompt 侧分叉信息：两条不同 prompt 序列可累计相同 token 数。

## 三 预注册结论（跑之前定死）

1. **主代理＝乙（累计 token），对照代理＝甲（前缀分叉位置）。** 本轮实验是固定 prompt 连续跑，甲在同 prompt 下退化、无组内区分度；乙逐点可加、可与 n_ctx 边界核对、可复现。甲贴近 KV 复用机制层，但只在换组换表/半重置条件下有区分度，作跨组对照代理，不承担同组内深度刻度。
2. **双记，不记单代理。** 每个读数同时落乙刻度（token 数）与甲读数（分叉位置/是否同前缀）；甲乙不一致（累计深但分叉早，或反之）记为混杂格，不强行归到带的某一档。
3. **刻度是连续轴，不是事后三档。** 浅/中/深不得跑完后按读数反画；乙为连续刻度，切点位置跑之前定，或跑完按分布定死，定后不事后挪动。
4. **两维分账。** 深度轴（乙）与温度轴（temp0 / temp0.3）分开记账，不混进同一格；满窗滚动格（累计 token 超 n_ctx）单列，不并入线性刻度。
5. **否证条件先定：** 人为截短前缀造深度实验，若中段（34 率 .5–.8 区间）在乙代理中间刻度复现不出，或双记显示深度与 34 率无单调关系，则「连续偏置带刻度」证伪；只保留方向结论（复用程度影响 34 率、方向单调），不保留有深度坐标分界的带。
